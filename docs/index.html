Notion catalog sync and a site passcode gate

Catalog → Notion

  • New /catalog/notion page previews the full, unfiltered catalog before pushing.
  • Push to Notion archives the old "Automation Catalog" sub-page and creates a fresh one, so there's always a single current copy.
  • Remove from Notion archives it without recreating.
  • Scenarios are grouped by Make.com folder into tables (name, status, last edited, next run), sent in batches under Notion's 100-block limit.
lib/notion.ts · api/catalog/notion · catalog/notion

Site gate

  • The whole site sits behind a shared passcode set in SITE_PASSCODE. Leaving it unset turns the gate off.
  • The cookie stores a SHA-256 hash, never the passcode, and lasts 30 days.
  • Changing the passcode signs everyone out on their next request.
  • Discord interactions and the monitor cron keep working because they skip the gate and use their own auth.
proxy.ts · lib/site-gate.ts · /gate · api/gate

Things to know

Check

The error monitor has nothing to watch yet. lib/watched-scenarios.ts is an empty list, so the cron endpoint runs but never alerts. Add scenario IDs there until the registry replaces it.

Decide

Registry datastore is still open: Notion (the original plan, easy for non-engineers to browse) or Supabase (already a dependency but unused, better for dedup and reconciliation queries). Pick one; the docs advise against building both.

Note

Nothing persists yet. Intake submissions go to Discord only, and the catalog reads live from the Make.com API on every page load with no cache.

Note

AI features run on Google Gemini (gemini-3.1-flash-lite-preview), not Claude. This is a deliberate departure from the original plan.

Next steps

In order. Each one unblocks the next.

  1. Choose the registry datastore and set it up per NOTION-SCHEMA.md.
  2. Write intake submissions into the registry as well as notifying Discord.
  3. Add effort and platform triage (Make.com vs. hosted) that writes back to the row, with a person still approving the move to Building.
  4. Put the build copilot on a page so /api/chat is reachable.
  5. Add the validate gate and the orphan detector once the registry is the source of truth.
